TP1 : La plateforme en code

Durée estimée : ~1h30

Point de départ : ton dépôt contient l'arborescence du TP0, l'application dans app/ et un .gitignore. Aucun cluster ne tourne (kind get clusters est vide).

Objectif : ne plus jamais créer le cluster à la main. À la fin, une seule commande reconstruit le cluster et ArgoCD.

Tout le code de ce TP va dans infra/. Les exemples complets sont dans les slides « Terraform en pratique ».

1. Le cluster

  1. Dans infra/versions.tf, déclare le provider tehcyx/kind.
  2. Dans infra/main.tf, déclare une ressource kind_cluster nommée plateforme, avec wait_for_ready = true.
  3. Lance terraform init, puis terraform plan. Lis le plan avant d'appliquer.
  4. Lance terraform apply.
kubectl --context kind-plateforme get nodes
terraform state list

Commite. Vérifie avec git status que ni le state ni le fichier plateforme-config ne sont proposés au commit.

2. ArgoCD

  1. Ajoute le provider hashicorp/helm et configure-le pour qu'il se connecte au cluster que tu viens de déclarer (quatre attributs de la ressource kind_cluster).
  2. Déclare une ressource helm_release nommée argocd (name = "argocd", c'est ce qui donne leur nom aux composants d'ArgoCD) qui installe le chart argo-cd du dépôt https://argoproj.github.io/argo-helm, dans le namespace argocd, en version 10.10.3, avec create_namespace = true et timeout = 600.
  3. terraform init (nouveau provider), terraform plan, terraform apply.
kubectl --context kind-plateforme -n argocd get pods

Attends que tous les pods soient Running, puis commite.

3. Ouvre l'interface d'ArgoCD

# le mot de passe du compte admin
kubectl --context kind-plateforme -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d ; echo

# l'interface sur https://localhost:8443 (laisse cette commande tourner)
kubectl --context kind-plateforme -n argocd port-forward svc/argocd-server 8443:443

Connecte-toi avec admin. L'interface est vide : c'est normal, tu n'as encore rien confié à ArgoCD. Tu y reviendras au TP2.

4. Des modules

Ton main.tf mélange deux sujets. Sépare-les.

  1. Crée infra/modules/cluster/ : la ressource kind_cluster, une variable nom, et les quatre output dont le provider Helm a besoin.
  2. Crée infra/modules/argocd/ : la ressource helm_release, une variable version_chart.
  3. Dans infra/main.tf, il ne reste que deux blocs module.
  4. Le provider Helm lit maintenant les sorties du module : module.cluster.endpoint, etc.
  5. terraform init (nouveaux modules), puis terraform plan.

Regarde bien ce plan : Terraform propose de détruire puis recréer tes ressources, parce que leur adresse a changé (kind_cluster.this est devenu module.cluster.kind_cluster.this). Sur une vraie infrastructure, ce serait une panne : on l'éviterait avec un bloc moved. Ici, c'est sans conséquence : applique.

5. Des variables

  1. Déclare dans infra/variables.tf les variables nom_cluster et version_argocd.
  2. Donne leurs valeurs dans infra/plateforme.tfvars.
  3. Plus aucune valeur en dur dans main.tf.
terraform apply -var-file=plateforme.tfvars

Attendu : No changes. Tu as réorganisé le code sans toucher à l'infrastructure. Commite, en vérifiant que plateforme.tfvars fait bien partie du commit.

Pièges connus

  • Le provider Helm ne trouve pas le cluster : ses quatre attributs doivent être des références à la ressource (ou au module), pas des valeurs copiées.
  • terraform apply semble bloqué sur helm_release : l'installation d'ArgoCD télécharge plusieurs images, compte une à trois minutes la première fois.
  • Tu as perdu ton terraform.tfstate alors que le cluster existe : Terraform ne sait plus qu'il est à lui. Supprime le cluster à la main (kind delete cluster --name plateforme) et relance terraform apply.
  • plateforme.tfvars n'est pas commité : ton .gitignore contient peut-être *.tfvars.

✅ Validation : ces deux commandes, l'une après l'autre, sans rien faire entre les deux, recréent le cluster et ArgoCD.

terraform destroy -var-file=plateforme.tfvars
terraform apply   -var-file=plateforme.tfvars
kubectl --context kind-plateforme -n argocd get deploy argocd-server     # 1/1

Puis, tout commité et poussé, lance le script de vérification depuis la racine du dépôt :

curl -fsSL https://raw.githubusercontent.com/DeepSnowNeeL/devops-avance-support/main/verifier.sh | bash
