TP0 : Remise à niveau

Durée estimée : 30′

Objectif : vérifier que ta machine est prête, retrouver les gestes de base de Kubernetes, et créer le dépôt dans lequel tu vas travailler pendant tout le cours.

1. Vérifie tes outils

Lance chaque commande. Si l'une échoue, installe l'outil avant d'aller plus loin (liens dans le README.md).

docker version --format '{{.Server.Version}}'
kind version
kubectl version --client
helm version --short
terraform version        # ou : tofu version
git --version

Docker doit tourner (Docker Desktop lancé). Il te faut environ 8 Go de mémoire libres : dans Docker Desktop, vérifie la mémoire allouée dans Settings > Resources.

2. Crée un cluster à la main

kind create cluster --name essai

Compte une trentaine de secondes. kind crée un cluster Kubernetes complet dans un conteneur Docker, et ajoute le contexte kind-essai à ta configuration kubectl.

kubectl --context kind-essai get nodes

Attends que le node soit Ready avant de continuer.

3. Lance un pod, observe, détruis

kubectl --context kind-essai run web --image=nginx:1.27 --port=80
kubectl --context kind-essai get pods --watch      # Ctrl+C quand il est Running
kubectl --context kind-essai describe pod web
kubectl --context kind-essai delete pod web

Réponds pour toi-même, sans chercher : quelle différence entre un pod et un deployment ? Que se passe-t-il si tu supprimes un pod qui appartient à un deployment ? Si tu hésites, crée un deployment (kubectl create deployment web --image=nginx:1.27), supprime son pod et regarde.

4. Détruis le cluster

kind delete cluster --name essai

Tu viens de créer et de détruire un cluster avec des commandes. Dans le TP1, tu ne taperas plus jamais kind create : ce sera du code.

5. Crée ton dépôt

Crée un dépôt public sur GitHub, à ton nom (par exemple plateforme-devops). Public, parce qu'ArgoCD devra le lire depuis ton cluster sans authentification. Clone-le, puis crée l'arborescence imposée :

mkdir -p infra app deploy/base deploy/overlays/dev deploy/overlays/prod deploy/argocd deploy/plateforme

Récupère l'application à déployer dans app/ :

git clone https://github.com/DeepSnowNeeL/devops-avance-support.git /tmp/support
cp /tmp/support/app/* app/

Copie aussi à la racine de ton dépôt les règles d'usage de l'IA du cours :

cp /tmp/support/racine/AGENTS.md /tmp/support/racine/CLAUDE.md .

Lis-les : si tu utilises un assistant de code, il les lira aussi. Il t'expliquera, il ne construira pas la plateforme à ta place.

Lis app/app.py (une soixantaine de lignes) : c'est une petite API qui expose des métriques et sait simuler des pannes. Tu ne la modifieras presque pas.

Écris un .gitignore avant tout le reste :

.terraform/
*.tfstate
*.tfstate.*
*-config

Git ne suit pas les dossiers vides : ajoute un fichier .gitkeep dans chaque dossier vide, puis fais ton premier commit et pousse.

Pièges connus

  • pods "web" is forbidden: error looking up service account default/default : tu as lancé le pod trop tôt, le cluster n'avait pas fini de démarrer. Attends que le node soit Ready et relance.
  • kind introuvable après installation sous Windows : ferme et rouvre ton terminal.
  • Sous WSL, avec un dépôt sur /mnt/c/..., git status montre tous les fichiers modifiés : ce sont les droits des fichiers, pas leur contenu. git config core.fileMode false dans le dépôt. Mieux : travaille dans ton répertoire personnel WSL (~/).
  • Le cluster ne démarre pas : Docker n'est pas lancé, ou il manque de mémoire.

L'historique compte

À partir de maintenant, l'historique de commits fait partie de l'évaluation. Des commits petits, fréquents, avec un message qui dit pourquoi. Le script de vérification refuse un dépôt qui contient des modifications non commitées ou non poussées.

✅ Validation : kubectl get pods t'a montré le pod web en Running, le cluster essai est détruit (kind get clusters ne l'affiche plus), et ton dépôt public contient l'arborescence, l'application et un premier commit.
