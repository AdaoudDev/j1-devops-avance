kind

kind get clusters
kind load docker-image api:initial --name plateforme     # charger une image locale
kind delete cluster --name plateforme                    # en dernier recours

Terraform (depuis infra/)

terraform init                                   # après tout nouveau provider ou module
terraform fmt -recursive                         # met le code en forme
terraform validate
terraform plan    -var-file=plateforme.tfvars
terraform apply   -var-file=plateforme.tfvars
terraform destroy -var-file=plateforme.tfvars
terraform state list                             # ce que Terraform pense avoir créé

kubectl

Ajoute --context kind-plateforme à chaque commande, ou fixe le contexte une fois : kubectl config use-context kind-plateforme.

kubectl get pods -A                                        # tous les pods du cluster
kubectl -n dev get deploy,svc,pods
kubectl -n dev describe pod <nom>                          # événements, raison d'un échec
kubectl -n dev logs deploy/api
kubectl -n dev port-forward svc/api 8080:80                # l'API sur localhost:8080
kubectl -n dev rollout restart deployment api
kubectl -n dev get deploy api -o jsonpath='{.spec.template.spec.containers[0].image}'

Kustomize

kubectl kustomize deploy/overlays/dev                      # affiche le résultat, n'applique rien
kubectl apply -k deploy/overlays/dev                       # applique à la main (dépannage)
kustomize edit set image api=<registry>/<image>:<tag>      # dans le pipeline

ArgoCD

kubectl -n argocd get applications
kubectl -n argocd describe application api-dev             # la raison d'un échec de synchro

# mot de passe du compte admin
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d ; echo
# interface sur https://localhost:8443
kubectl -n argocd port-forward svc/argocd-server 8443:443
État Sens
Synced / OutOfSync le cluster correspond, ou non, à git
Healthy / Progressing / Degraded ce qui est déployé fonctionne, démarre, ou échoue
Unknown ArgoCD n'arrive pas à lire le dépôt

Sealed Secrets

kubectl create secret generic api-secret --namespace dev \
    --from-literal=JETON=<valeur> --dry-run=client -o yaml \
  | kubeseal --context kind-plateforme --format yaml \
  > deploy/overlays/dev/api-secret-scelle.yaml

kubectl -n dev get sealedsecret,secret

L'application

curl localhost:8080/                                # service, version, jeton_present
curl localhost:8080/metrics                         # métriques Prometheus
curl "localhost:8080/chaos?erreurs=0.3&latence=500" # 30 % d'erreurs, 500 ms de latence
curl "localhost:8080/chaos?erreurs=0&latence=0"     # retour à la normale

Tout reconstruire

cd infra
terraform destroy -var-file=plateforme.tfvars
terraform apply   -var-file=plateforme.tfvars

Après une reconstruction : resceller le secret (la clé du contrôleur a changé), et tant que le pipeline n'a pas déployé, recharger l'image api:initial dans le cluster.
